## 3. 진단 콘텐츠 및 채점 로직 요약

### 3.1 5대 카테고리 구성 (총 30문항, 4지선다)
1. **세액감면 (`tax`)**: 절세 적극성, 벤처소득공제, 가족법인, 컨설팅 빈도, 세무리스크, 법인잉여금 (만점 73점)
2. **부동산 활용 (`realestate`)**: 사옥 형태, 투자 부동산, 투자 의향, 투자 경험, 대출 규모, Value Up (만점 83점)
3. **가업승계 (`succession`)**: 후계자 상태, 승계 시기, 가업상속공제, 현물출자, 자녀법인, 신탁 (만점 76점)
4. **은퇴설계 (`retirement`)**: 은퇴 시점, 노후 자금, 연금/IRP, 자산 배분, 인출 전략, 상속/증여 (만점 72점)
5. **경영지원 (`management`)**: 법인 단계, 자금 조달, IR/지분, 세무회계 시스템, 노무리스크, 조직체계 (만점 72점)

### 3.2 100점 환산 및 4단계 등급 컷오프
$$\text{잠재 기회 지수(Score)} = \text{round}\left( \frac{\sum \text{선택 점수}}{\sum \text{카테고리 문항별 최대 점수}} \times 100 \right)$$

* **S등급 (80점 이상)**: 전략적 최적화 단계 (ROI 극대화 로드맵 제안)
* **A등급 (60점 ~ 79점)**: 숨은 기회 존재 (놓치고 있는 절세/승계 기회 점검)
* **B등급 (40점 ~ 59점)**: 리스크 노출 시점 (매년 누수되는 세금/손해 차단)
* **C등급 (40점 미만)**: 긴급 점검 필요 (전 영역 리스크 동시 노출, 즉각 구조 개편)

## 4. 백엔드 연동 및 전송 데이터 스펙

### 4.1 전송 Payload 필드 (17개 공통 필드 + Q1~Q6)
* `session_id`, `timestamp`, `completed`(true/false), `category`, `group`, `last_question`, `time_taken_seconds`, `score`, `grade`, `email`, `newsletter_consent`, `q0_asset_size`, `q1`~`q6`, `user_agent`, `screen_width`, `screen_height`, `referrer`

### 4.2 주요 처리 정책
1. **이중 전송 메커니즘**: 완주 시 `fetch()`, 이탈 시 `sendBeacon()`으로 전송하여 이탈률 데이터 확보 (`index.html:2020-2040`).
2. **무음 실패(Silent Fail)**: 통신 에러 발생 시 사용자 흐름을 방해하지 않기 위해 무음 처리됨 (`index.html:2026`).
3. **이메일 발송**: `completed === true`이고 유효 이메일 존재 시 `MailApp.sendEmail()`로 결과 리포트 즉시 발송 (`apps-script.gs:107-115`).

## 6. 긴급 개선 과제 (우선순위별 Action Items)

### [P0 - 즉시 수정 필요 (법적/문법 리스크)]
1. **개인정보 수집 문구 모순 해결 (법적 리스크)**:
   * 인트로의 *"수집하지 않음: 이메일"* 문구(`index.html:1626`)와 동의폼의 *"이메일 필수"* 요구(`index.html:1769`)가 충돌하므로, 인트로 문구를 즉시 정정하고 푸터에 개인정보처리방침 링크를 추가해야 합니다.
2. **HTML 중복 종료 태그 삭제**:
   * `index.html:2645-2646`에 잘못 들어간 중복 `</body></html>` 태그를 제거해야 합니다.
3. **이메일 제출 중복 클릭(Double Submit) 방지**:
   * `submitConsent()`에 버튼 `disabled` 처리를 추가하여 시트 다중 저장 및 메일 중복 발송을 방지해야 합니다.

### [P1 - 조속한 개선 권장 (UX 단절 해소)]
1. **1번 문항에서 카테고리 재선택 뒤로가기 허용**:
   * 카테고리를 잘못 선택한 사용자가 새로고침 없이 카테고리 화면으로 갈 수 있도록 `goBack()` 분기를 개선합니다.
2. **동의 화면(`#screen-consent`) 뒤로가기 버튼 신설**:
   * 이메일 입력 전 문항 답변을 수정할 수 있도록 뒤로가기 네비게이션을 제공합니다.
3. **이메일 정규식 유효성 검증 강화**:
   * 잘못된 도메인이나 허위 이메일 유입을 방지하도록 정규식을 고도화합니다.

### [P2 - 점진적 리팩토링]
1. **단일 HTML 모듈화 분리**: `css/`, `js/config.js`, `js/app.js`, `js/analytics.js` 등으로 분리하여 캐싱 및 유지보수성을 극대화합니다.
2. **미사용 레거시 코드 제거**: `index.html:2063-2165`의 미사용 `QUESTIONS` 배열(102줄)을 정리합니다.
3. **Kakao SDK 정식 키 등록**: `index.html:2446`에 카카오 개발자 JavaScript 키를 발급받아 등록합니다.
